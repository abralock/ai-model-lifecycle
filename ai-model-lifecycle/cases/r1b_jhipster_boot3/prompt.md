# Task: Upgrade a real application from Spring Boot 2.7 to Spring Boot 3

The attached project is the backend of a real open-source application: the
JHipster sample app (`jhipsterSampleApplication`, generated by JHipster 7.9.3),
a bank-account manager with JWT authentication, users and admin APIs, JPA
entities, Liquibase migrations, an Ehcache second-level cache, mail, and
RFC 7807 problem responses. It runs on **Spring Boot 2.7.3 and Java 11**.

Upgrade it to **Spring Boot 3.x on Java 17** (Jakarta EE 10, Hibernate 6,
Spring Security 6). The project's libraries must move to versions that support
Boot 3 as well, including the JHipster framework libraries (`tech.jhipster`).

## Acceptance criteria (this is how your work is checked)

1. The build passes with Maven 3.8 and Java 17: `mvn -P-webapp verify`
   (`-P-webapp` skips the Angular frontend; checkstyle and modernizer still run).
2. The project's existing test suite passes: 52 unit tests and 140 integration
   tests (integration tests run on an in-memory H2 database). The test sources
   under `src/test/` are **maintained separately and are already migrated to
   Boot 3**. Do not write or edit anything under `src/test/`; your changes there
   are discarded. The suite contains, among others: `AccountResourceIT`,
   `UserResourceIT`, `BankAccountResourceIT`, `LabelResourceIT`,
   `OperationResourceIT`, `UserJWTControllerIT`, `ExceptionTranslatorIT`,
   `MailServiceIT`, `UserServiceIT`, `HibernateTimeZoneIT`, `ClientForwardControllerTest`,
   `TechnicalStructureTest` (ArchUnit) and `WebConfigurerTest`. The suite
   uses the ArchUnit 1.x API (`layeredArchitecture().consideringAllDependencies()`),
   so the project's test dependencies must provide it.
3. The REST API keeps its behavior: same endpoints, same security rules, same
   JWT login, same JSON bodies, and the same problem (error) response format.
   The unchanged Angular frontend and its Cypress end-to-end suite are run
   against your backend.
4. No Jakarta EE APIs are still used through their old `javax.*` packages
   (`javax.persistence`, `javax.validation`, `javax.servlet`, `javax.mail`,
   `javax.annotation.PostConstruct`/`Generated`, ...). Packages that did not move
   (`javax.cache`, `javax.sql`, JSR-305 `javax.annotation.Nonnull`, ...) are fine.

## Output format

Paths are relative to the project root (`pom.xml`, `src/main/...`), not to the
`project/` folder of the case listing.

Prefer **edits** over rewriting whole files. For each file you change, emit one
`### EDIT:` header followed by one or more SEARCH/REPLACE blocks. The SEARCH
text must match the current file exactly (copy it, including indentation) and
should be just long enough to be unique; the first match is replaced.

````
### EDIT: src/main/java/io/github/jhipster/sample/domain/Label.java
```java
<<<<<<< SEARCH
import javax.persistence.*;
=======
import jakarta.persistence.*;
>>>>>>> REPLACE
```
````

To create a file or replace one completely, emit it whole instead:

````
### FILE: src/main/java/io/github/jhipster/sample/config/NewConfig.java
```java
...full file content...
```
````

To remove a file, emit a single line `### DELETE: <path>`.

Files you do not mention stay exactly as they are. Do not add commentary
outside these blocks.
